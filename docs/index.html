What This Project Is Testing

Can a very small local decoder learn useful language if the training setup is disciplined enough?

1

Base language first

OCR, instruction parsing, and autocomplete are deliberately paused until continuation quality is stable.

2

Controlled size ablation

Tokenizer, data, context, optimizer, validation split, and token budget stay fixed while capacity changes.

3

Evidence over vibes

Every run is judged with validation loss, perplexity, speed, plots, and fixed prompt samples.

Key Learnings

The data pipeline is working; the main bottleneck has moved to corpus quality and balance.

Data matters

The 40M v2 run cut best perplexity from 36.55 to 22.94 versus the older 40M baseline.

Tokens are not enough

The 10M model saw the most tokens per parameter and still had the worst validation loss.

Loss needs samples

The best loss still produced shallow continuations, so fixed prompt checks remain necessary.

Decoding is next

Greedy samples still repeat, so fixed decoding checks and stronger sampling tests are needed before task training.

Next: fix repetition before task training.

Keep lm_40m_v2 as the new base checkpoint, but treat it as a better LM baseline rather than a task-ready model.

1Evaluate more prompts with greedy, top-k, and nucleus sampling to separate model repetition from decoding repetition.
2Inspect lm_prose_v2 for repeated boilerplate that may still be teaching phrase loops.
3Keep the 40M v2 checkpoint as the baseline for any next corpus cleanup.
4Only run task finetuning after fixed prompt samples stop collapsing into repeated clauses.
5When task training resumes, mix continued LM data to reduce forgetting and style collapse.
