Tiny decoder ablation study

How far can a very small decoder learn language?

This project compares 9M, 20M, 31M, and 40M parameter decoder-only language models trained from scratch under a controlled local setup. The current answer: the 40M model is the best baseline, but corpus quality is now the bottleneck.

Project Goal

The objective is not to build a large general assistant. The objective is to learn how much language capability can be extracted from tiny decoders when data, tokenizer, optimizer, context length, and token budget are controlled.

Base LM first

Train plain continuation before adding OCR, instruction, or autocomplete behavior.

Controlled ablation

Keep the dataset and optimizer fixed while comparing model size.

Local constraint

Use conservative batches and gradient accumulation for small GPU training.

Evidence driven

Use validation loss, perplexity, plots, and fixed prompt samples together.

Iteration History

The project has moved from mixed task training to a cleaner base-LM-first ablation.

Iteration 1

Mixed-stage training failed as a language model

A 20M decoder completed Stage 1, Stage 2, and Stage 3, but generation fell into token loops. Padding was trained as a target, the base data was fragmented, and task finetuning arrived before the base LM was coherent.

Iteration 2

Base LM first

The project reset around packed text chunks, ignored padding labels, no label smoothing, and controlled comparisons between 10M, 20M, 30M, and 40M parameter configs.

2026-06-15

Full Stage 1 language ablation

All four model sizes trained for 248,500 steps on the same lm_prose corpus, each seeing 4.071B token slots. The 40M model won by validation loss and qualitative readability.

Where We Stand

The ablation is useful and the ranking is clear, but the decoder is not finished.

Current state: lm_40m is the best checkpoint family so far, but it is still a baseline. It can produce readable text, yet the language remains generic, shallow, repetitive, and biased toward app-description phrasing. 
The best place to visit in => the world. The best place to visit is where you can easily find and view more than one hundred people who can be visiting.
A smartphone camera app can => be installed by using its iPhone or iPad. A mobile phone is a device that uses an iOS device...

Key Learnings

The current bottleneck is no longer whether the training loop works. It is data quality and base language behavior.

  • Capacity matters.The 40M model has the best validation loss and about 46 percent lower final perplexity than the 10M model.
  • Tokens per parameter are not enough.The 10M model saw the most tokens per parameter but still had the weakest validation loss.
  • Loss is not the whole story.The best loss still produced shallow samples, so prompt checks must stay in the loop.
  • Task training should wait.OCR, instruction parsing, and autocomplete should resume only after the base LM is stronger.

Recommended Next Step

Continue with the 40M config, but do not simply train more on the same corpus.

  1. Build lm_prose_v2 with cleaner and broader packed prose.
  2. Reduce repeated app-store and feature-list style text.
  3. Keep packed 256-token chunks so the run stays comparable.
  4. Train lm_40m first against the new corpus.
  5. Compare validation loss, perplexity, and fixed prompt samples against the 2026-06-15 baseline.
  6. Run 20M or 30M controls only after the 40M v2 result proves the data improved language behavior.
